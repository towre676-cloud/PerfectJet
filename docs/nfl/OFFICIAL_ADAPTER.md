# Official Big Data Bowl 2027 adapter

`perfectjet.applications.nfl_scouting.official.load_official_directory` accepts a directory containing the nine original official competition CSV files. It returns the existing `Dataset` contract with `synthetic=False`. It does not acquire credentials, invent observations, silently use synthetic data, or publish individual records. Missing filenames are reported explicitly. The adapter hashes all nine inputs; `verify_known_hashes=True` additionally requires the exact SHA-256 values retained in the canonical research archive's `receipts/actual/acquisition.json`. A hash match establishes snapshot identity, not predictive success.

```python
from perfectjet.applications.nfl_scouting.official import load_official_directory

dataset = load_official_directory(
    "/path/to/private/official_data",
    minimum_plays=30,
    verify_known_hashes=True,
)
audit = dataset.manifest["official_adapter"]["audit"]
```

The input filenames are `combine_results.csv`, `combine_tracking.csv`, `players.csv`, `player_play.csv`, `games.csv`, `player_career_successes.csv`, and `game_tracking_2023.csv`, `game_tracking_2024.csv`, `game_tracking_2025.csv`. Career-success values are hashed for source identity but never loaded as predictors. Draft picks, NFL position, and NFL outcomes are likewise excluded from athlete measurements. IDs are parsed as exact decimal integers, so an identifier larger than the binary floating-point exact-integer range cannot silently join to a neighboring athlete. Duplicate metadata identities and duplicate player/play records raise an error.

The defensive-front selection uses `combine_results.combine_position`, not the future NFL position. Default accepted positions are DE, DT, NT, OLB, EDGE and DL; users can declare a different position set explicitly. A generic LB designation is not automatically assumed to mean an outside pass rusher. The selected drills are pass rush, hoop, four-bag agility, front-start wave/lateral reaction, and the forty-yard dash. Each attempt retains its original drill name and event identity. Ball rows and other entities are excluded. ISO timestamps provide elapsed seconds; coordinates stay in yards. The adapter accepts contiguous 10 Hz frames with a 0.015-second interval tolerance and rejects duplicate frames, missing frames, nonfinite coordinates, short attempts, mismatched draft years and observations later than the declared April 20 pre-draft cutoff. The minimum length defaults to sixteen frames and is separately configurable.

The official physical-result table has no per-measurement publication dates. All fifteen body, timed-test and NGS values are exposed, with the latest accepted tracked Combine date per athlete recorded as an explicitly inferred availability proxy. This is not evidence for the exact publication time of an NGS grade. NGS chronology remains flagged as unverified in the manifest. Any model using those scores must declare its pre-draft interpretation, and a no-NGS sensitivity should accompany the stronger comparator. The eight legacy names are mapped to `height`, `weight`, `forty`, `vertical`, `broad`, `three_cone`, `shuttle` and `bench`; additional fields retain their official names. NFL context never enters the `Athlete` record.

The primary label is the official `player_get_off`: supplied elapsed seconds from ball snap to crossing the line of scrimmage. It is not pure reaction time. Eligible records belong to the athlete's rookie regular season, are explicitly non-nullified by penalty, and contain finite nonnegative charted get-off. With the default snap context, each record must also match exactly one finite ball-snap observation. The adapter streams each required season's game-tracking file once and retains only selected ball-snap rows. The player must have at least thirty remaining eligible records, with the threshold reapplied after missing and nonunique snap exclusions. Athletes with usable Combine attempts but no eligible outcome remain represented as missing-outcome athletes; no target of zero is invented.

The signed snap depth is `(x - LOS) * direction`, where direction is +1 for right-moving offense and -1 for left-moving offense. If the yardline is on the possession team's side, the offensive yard coordinate is `yardline_number`; otherwise it is `100 - yardline_number`. LOS is `10 + yards` when moving right and `110 - yards` when moving left. Width is the absolute displacement from field center, `abs(y - 80/3)`, in yards; speed is the recorded ball-snap speed in yards per second. These variables, alignment and situation are outcome-normalization context only. Future NFL roles must not be supplied as pre-draft predictor inputs. `include_snap_context=False` is an explicit alternative outcome-context experiment and changes the eligible population; it is recorded in the manifest.

The audit reports accepted attempts, source rejections, eligible records and athletes, missing and nonunique snaps, tracked athletes lacking an eligible outcome, unmatched player/game IDs, and rookie/season/penalty exclusions. The Combine-position cohort can differ from the historical NFL-position-selected cohort; such differences must be reported rather than forcing the old seventy-four-athlete count. Raw CSVs and individual derived records belong in private local data/output directories and are excluded from published source packages. Aggregate findings, code, configurations and source hashes can be packaged separately.

The small fixture tests exercise the actual official column names, exact large-ID joins, contradictory Combine/NFL positions, future/preseason/postseason and nullified-play exclusions, timestamp-derived units, direction-aware LOS geometry, unique-snap requirements, and the post-exclusion minimum count. These are contract and leakage safeguards, not a claim that a predictive breakthrough has occurred.
